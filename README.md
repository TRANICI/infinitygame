# 零号病区 · WARD ZERO

第一人称网页恐怖调查游戏。当前集中制作第一关「零号院区 · 未完夜班」，第 2、3、4 关已暂时退出游戏，原章节资料保存在 `archive/`，不随游戏加载或打包。

林秋收到妹妹的求救语音，回到关闭三年的医院，却发现每天都有自己的值班签名。剧情使用口语、反复改口与身份冒用制造异常感，操作线索直接说明。[完整剧情](design/story.md) · [玩家视角审查](design/player-review.md) · [代班者设计](design/pursuer/README.md)。代班者现已接入实机，具有低多边形模型、巡查、追逐、声源调查、丢失目标后搜查、凝视紧张反馈和近身突脸。采用简化画面与局部照明；墙壁按用户要求回退为更早的灰黄细颗粒材质，不使用写实血肉贴图。

当前为夜班调查场景：旧地名已替换成候诊庭院、病历交接廊、救护庭院、门诊长街、值班入口等院区名称。较低的环境照明、远处薄雾、封院告示、封死的井口和重复处方共同塑造异常感。原有几何轮廓仍是改造基础，沿途可进入附属房间。

双击 `开始游戏.bat` 或 `index.html`。也可以运行 `npm start`，打开 `http://127.0.0.1:4173`。运行无需下载依赖，桌面端推荐 Chrome / Edge；手机支持触屏移动、观察、跳跃与解谜。

## 院区附属房间与物品交互

这六间小房间直接开在原院区道路旁，不必先去东侧旧档案翼。入口按相邻道路标高连接；房门可开关，关闭后遮断视线并改变导航。门口有人时禁止关门，避免把玩家或巡夜者卡进门体。病历保管室需要钥匙，其余房间可直接开门。

| 编号 | 房间 / 所在路线 | 交互与用途 |
| --- | --- | --- |
| R01 | 封存杂物间 / 候诊庭院旁 | 搜索黄铜钥匙和两个空瓶 |
| R02 | 转运维修间 / 地下转运道旁 | 搜索可重复使用的绝缘螺丝刀 |
| R03 | 病历保管室 / 病历交接廊旁 | 用钥匙开门，搜索备用线材 |
| R04 | 失联通讯室 / 救护庭院旁 | 用工具和线材维修，选择远端区域播放诱导广播 |
| R05 | 夜班茶水间 / 门诊长街旁 | 投币购买汽水；喝下补满体力并获得空瓶 |
| R06 | 停用门卫室 / 值班入口旁 | 搜索两枚硬币和路线提示 |

每间房另有一个躲藏柜。搜寻只发放一次物品；购买、使用和投掷扣除对应数量；满体力时不会浪费汽水；贴墙或躲藏时不能投瓶。广播和空瓶可吸引未锁定玩家的代班者；已经被看见时，先转角遮断视线。地图按探索范围标注房间，背包保存物品用途及抄录的异常记录。旧存档缺少这些字段时会自动初始化，不影响原主线。

### 院区谜题与可改造路线

- 值班入口：读分诊牌，工具柜输入 317，取得撬棍。
- 候诊庭院：排水泵有 +1 / +2 / +3 三个阀门，开 1 和 3，把压力调到 4，取备用保险芯。
- 消毒连廊：撬掉木板，使用保险芯和螺丝刀修大门，形成返回门诊方向的近路。
- 夜班茶水间：后窗可用螺丝刀安静拆下，或用撬棍砸开；补给柜按交班条设置冷藏 / 每次两片 / 每天三次，取得汽水与空瓶。

新增屏风与转运床分隔开阔视线。物件 4.5 米内有柔和微光，受朝向、墙体、楼层遮挡限制；暖白可查看，琥珀色缺工具，完成后熄灭。交互距离按物件表面计算，宽门边缘也能操作。开启后的门窗、拆掉的木板同步更新画面、碰撞、地图和存档。新路线是支线，不会阻断原主线。

## 第一关流程

1. 在 候诊庭院、病历交接廊、门诊长街找齐三张号码牌，放入 广播庭院庭院广播台，授权总电源。
2. 从 门诊长街东侧连接廊进入旧档案翼。接待厅、配电室有可阅读的维修线索。
3. 调整三路配电柜，合闸检验，恢复门禁和档案供电。
4. 根据时钟与维修单，输入四位时间密码，打开回廊门。
5. 探索 5 × 5 回廊迷宫，在不同分支找齐「日 / 雨 / 月」交班印章。通道宽 3 米，有岔路、环路和死胡同，可查看地图。
6. 在迷宫南侧离岗广播室，根据接待厅三格画排列印章，确认离岗，不签新的交接单。
7. 广播室西侧门闩能打开应急回廊，沿捷径返回庭院，再从北侧出口结束第一关。

机关和线索界面会暂停游戏。输错密码、接线或印章顺序可以重试，不会丢失收集物。每一步及未合闸的开关状态自动保存；旧版第一关的号码牌、设备和明信片存档仍可继续，新调查从头开始。旧第 2–4 关存档不再显示继续入口。

花园、广播台、停业药房三段支线改成异常交接单，揭示重复签到和剪接求救录音。庭院录音机、支路配电箱、档案抽屉和试音铃保留；这些设备与旧档案翼的主线配电柜分别操作。已读现场纸条及支线记录汇集到 J 笔记中。

### 北翼与后勤支线

配电室北侧新增值班休息室、诊疗室、217 病房；时间门禁之后新增黄灯候诊厅、洗衣房、循环泵房、器材库、观察室，共 8 间有独立配色、编号与家具的房间。北翼与接待厅门禁共用同一密码，不会绕过主线供电条件。

黄灯候诊厅与洗衣房形成第一条环路，南侧后勤走廊围绕泵房形成第二条环路；泵房横穿路线提供追逐中的换向选择。洗衣房、泵房各有一处水阀，全部关闭后可在器材库开启通往广播室的永久捷径。这个支线不替代三枚印章。新增 4 份叙事线索、5 个躲藏柜与 1 个呼叫铃，水阀和捷径状态自动保存，旧存档也能继续。

代班者沿实体道路移动，不能隔墙抓人。丢失视线后只跟进最后看见的位置，约 7 秒后转为搜查，躲藏不会持续暴露新坐标。机关与笔记界面会暂停游戏。

地图可切换「已探索 / 庭院 / 旧翼放大」。只有探索到的地面、房间编号、地点和物件会显示；未知区域保持黑色，房间名称列表也不会提前透露。探索以 3 米单元记录，视线受墙体及楼层限制，范围随存档保留。新游戏清空地图，被捕保留地图。关卡使用本项目原创布局。

## 地图与性能

庭院主体依据用户提供的 820 × 805 Dust II 鸟瞰图描摹，比例 0.14 游戏米/像素。高低关系参考本地 CS2 `de_dust2.nav` v36 的 2,242 个区域，使用平整平台和 0.18 米实体楼梯，保留 CT 下穿与上层小道。墙高、家具与材质为简化重建。

旧档案翼向地图东侧与北侧扩展，包围范围为 101 × 68 米，包含连接廊、接待厅、配电室、回廊迷宫、广播室、应急回廊，以及 8 间北翼与后勤房间。范围内包含墙体和空区，并非全部可走。连接处与 门诊长街同为 4.68 米高，使用平地，无斜坡。地面、墙体、导航和地图共用同一份占地数据，边界自动根据房间占地计算。

碰撞按空间分区，扩展区地面查询使用栅格缓存，静态地图与互动网格分别上传。微光只更新独立的小网格，不重建场景。后台标签停止渲染。F3 可查看自己设备上的表现；自动化浏览器基准不代表所有设备的帧率。

## 开发与验证

```text
npm run check                  # JavaScript 语法
npm test                       # 原有通路、楼梯、跳跃、跌落，以及新增区域实际行走与门锁
python tests/room-ui.py         # 背包、开锁、修复、地图、手机布局；无鼠标锁定
python tests/horror-ui.py       # 院区谜题、障碍状态、剧情结局；隔离追逐随机性，无鼠标锁定
python tests/pursuit-ui.py      # 实机追逐模型、突脸与关闭选项、恢复、探索地图和手机显示
npm run build                  # 生成离线纯静态 dist/
python tests/packaged.py        # 在 /infinitygame/ 子路径运行两套安全界面测试
```

浏览器测试需要 Python Playwright 与 Chrome。以上界面测试使用 headless Chrome，通过 DOM 调用并拦截原生鼠标锁定，不控制桌面鼠标。`test-results/` 是本地测试输出，不进入游戏包。旧 `smoke.py`、`expansion.py` 等脚本保留早期输入和追逐测试，不作为当前版本的验收入口。

- `core.js`：当前关卡、碰撞、物件和寻路。
- `annex.js`：扩展区占地、固定种子迷宫、线索与交互位置。
- `courtyard-rooms.js`：原院区边缘六间小房间、门、物件及高度。
- `interactions.js`：背包、钥匙、搜寻、修复、购买、消耗品、投掷与持久化。
- `investigation.js`：主线机关、笔记、门锁状态与存档恢复。
- `terrain.js`：分层高度、楼梯和导航。
- `world3d.js`：WebGL 地形、家具、门窗、机关和近距微光。
- `dust2-layout.js` / `dust2-scene.js`：庭院主体轮廓及场景内容。
- `dust2-architecture.js`：生成后的平台与楼梯。
- `scripts/build-architecture.cjs`：重建建筑地形，修改后需运行路线检查。
- `archive/`：暂时移除的章节资料，不加载、不打包。
- `design/`：剧情、玩家视角审查、代班者概念图与预留方案，不加载、不打包。

导航格式参考 [ValveResourceFormat](https://github.com/ValveResourceFormat/ValveResourceFormat/tree/master/ValveResourceFormat/NavMesh)。运行时不访问 Steam 目录，无外部材质或网络依赖。
